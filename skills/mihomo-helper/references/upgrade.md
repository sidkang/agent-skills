# 升级 mihomo 核心

只在用户明确要求升级/更新核心时执行。沿用 [安装](install.md) 的官方 latest API、镜像连通性预检、校验和与下载来源选择；不要以旧示例版本或浏览器缓存当 latest。确认 Windows 架构、目标资产名和发布说明；官方直连优先，镜像只作用户接受风险后的备选。下载/检查期间不改当前核心。

记录旧版二进制版本、路径、配置路径、登录自启任务状态，以及本地配置与节点/规则缓存所在目录。升级前备份 Program Files 内旧 exe 和当前用户配置文件，确认下载包与官方 SHA256（若发布了）一致、可正常解压、目标 Windows 防火墙规则不会失效；不要把私有订阅存到公共日志或临时共享目录。

在有授权的维护窗口停止由本 skill 创建的任务及其进程，**只更换程序二进制**，保留 `%USERPROFILE%\config\mihomo\`（或用户指定的数据目录）的配置、provider 和规则缓存；不要清空状态、顺手同步到别的 profile 或覆盖用户自定文件。按实际 exe 名称确认任务执行路径仍指向新版；允许用户选择先手工启动验证，再恢复登录后启动。检查版本、TUN/DNS、国内直连、GitHub 与显式代理服务，核查规则和节点 provider 是否继续更新。

若新版不能运行或导致连通性问题，停止该任务，用备份的旧 exe 恢复；配置若确需回滚，仅恢复用户确认的对应备份。恢复任务及先前网络状态，说明当前运行版本和未解决的问题。配置验证仅在实际 Windows 环境与节点具备、且用户允许部署时进行；写模板时不宣称做过运行测试。
