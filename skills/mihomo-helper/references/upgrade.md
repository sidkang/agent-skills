# 升级核心

用户明确要求升级后，按 [安装](install.md#下载) 查询当次稳定版及说明，核对架构、资产与官方摘要；下载期间保持旧核心运行。仅问影响不等于执行升级。

记录实际用户、实例、-d/-f、版本、二进制/配置 SHA256、任务定义及启用/运行状态。默认只替换二进制，保留配置、provider 缓存和状态；需要改配置须有对应范围授权。

按 [本地事务入口](validation.md#本地事务入口) 提交计划：在停止旧核心前暂存候选、备份原文件和任务状态，以候选核心做限时 -t，并确认独立 watchdog 已实际启动。临时 -d 不等于安全沙盒；兼容性检查可能访问 provider/绝对路径，须在相应授权内执行。未知字段可能被忽略，empty-fallback/UDP guard 还需语义验证。

Apply 完成只代表本地候选已应用，状态为 PendingValidation，不代表网络成功。检查版本、TUN/DNS、直连/内网、指定服务 rule/rulePayload/chains/地区和 provider 更新后，才能 Commit。失败或未在期限内确认则由本地机制恢复旧文件、原运行状态与任务启用状态；Agent 会话中断不取消 watchdog。

脚本只控制已验证路径和参数的单实例，不按 mihomo.exe 名称批量终止。shell 包装、多实例、不同账户或并发改动会拒绝执行。回滚无法解决的文件/权限冲突须报告 RecoveryFailed 和本地快照位置，不伪报恢复成功。交付列出实际版本、三层检查结果和未验证项。
